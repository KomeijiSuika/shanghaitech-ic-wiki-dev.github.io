# 参与共建

修正一处错字、补充一条引用、撰写一段实践经验，都是本项目欢迎的贡献。请选择适合当前材料的入口。

## 报告问题或推荐资源

在[创建议题]({{ repo_url }}/issues/new/choose)中选择错误反馈、资源推荐、内容投稿或功能建议。请给出涉及的页面、原始来源，以及希望解决的问题。开始长篇投稿前，可以先到[现有议题]({{ repo_url }}/issues)查看是否有人正在整理同一主题。

## 直接修改页面

1. 打开目标文章，点击标题旁的编辑按钮，进入该页面的 GitHub 源文件。
2. 登录 GitHub，按提示 Fork（派生）仓库，在新分支上修改 Markdown。使用预览查看标题、列表与链接。
3. 将修改保存到自己的分支，向上游仓库的 `main` 发起 Pull Request（合并请求）。说明改动的理由，并附上资料来源。
4. 查看构建检查和维护者的反馈。若需要补充，继续向同一分支提交。合并后网站会自动发布。

## 新增一篇文章

从[内容模板]({{ repo_url }}/tree/main/templates)选一份，复制到 `docs/` 下最相关的目录，文件名使用小写英文和连字符。将新页面加入 `mkdocs.yml` 的 `nav`，同时在板块首页添加入口。更多命令和审核标准见[仓库贡献指南]({{ repo_url }}/blob/main/CONTRIBUTING.md)。

## 投稿前核对

- 可以区分官方信息与个人经验，并注明适用时间或软件版本。
- 引用提供作者、材料题名与可访问的原始链接。图片、表格、代码均有明确的使用依据。
- 仅公开可以合法分享的材料，已处理个人信息、受限课件和保密内容。
- Markdown 和站内链接可正常预览。复杂排版可对照[文章写作示例](writing.md)。
